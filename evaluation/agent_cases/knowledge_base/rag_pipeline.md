# RAG 检索问答流程

这份文档说明内部演示系统如何使用证据回答问题。它是受控知识库的流程资料，术语用于这些测试场景，不代表任何外部服务的实现承诺。

## 定义
RAG 将检索与生成结合：系统先从知识库取得相关资料，再让语言模型根据资料生成回答。知识库资料可以随索引更新，回答中的事实需要由本次提供的证据支持。模型自身记得某个事实不等于知识库已经提供它。

## 流程
文档先被加载和切块，再进入检索阶段。Retrieval 负责召回候选，Rerank 对候选重新排序，Generation 根据最终证据组织答案。团队使用 BM25 与 Dense 两路召回，并通过 RRF 融合排名；是否有效要通过固定测试集检验。

## 证据不足
Evidence Sufficiency 判断证据是否覆盖问题的主要信息需求。证据不足时先列出缺失信息，再决定是否继续检索。搜索预算耗尽仍没有依据时，应说明缺少什么，只回答已知部分，不能把推测写成知识库结论。

## 查询改写
Query Rewrite 根据缺失信息构造新的检索查询，同时保留原问题中的实体和约束。改写的目的是补充证据，不是换句话重复同一搜索，也不保证必然找到答案。一次改写是否有帮助，应检查是否带来了新的有效信息。
