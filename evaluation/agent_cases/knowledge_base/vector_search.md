# 向量检索使用说明

本说明面向内部知识库检索组件。实验比较使用同一批文档和查询，控制文档切块及候选数量，避免把数据变化误认为算法改进。

## 向量表示
Dense Retrieval 使用 Embedding 将文本编码为向量，再通过向量相似度召回候选。查询和文档必须采用兼容的编码方式。它能处理部分同义表达，但高相似度不等于事实正确，也不能代替证据充分性判断。

## FAISS
FAISS 是向量相似性搜索工具，可以建立向量索引并返回相似向量的位置和分数。系统还需要保存向量与文档片段的映射，才能恢复可读内容和来源。索引本身不负责生成答案，也不自动理解引用是否正确。

## 关键词互补
BM25 基于词项匹配，适合技术标识符、版本号及精确实体；Dense 侧重语义相似性。混合检索把两类候选结合，以覆盖不同查询表达。融合需要处理排名差异，不能直接把来源不同的原始分数当成同一尺度相加。

## 边界
最终结果仍需检查是否覆盖任务要求。向量检索可能召回语义相近但项目不同的材料；对 Orion 和 Lyra 的版本比较必须保留实体名。本文没有任何语料上的固定准确率，也没有说明使用 FAISS 就必然优于所有关键词系统。
