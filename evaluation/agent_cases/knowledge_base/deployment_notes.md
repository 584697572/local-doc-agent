# 演示部署记录

本文汇总两个虚构项目的验证环境和运维约定。资源下限来自固定的演示场景，不是生产容量规划，也不代表在任意文档规模下都能保持相同性能。

## Orion环境
Orion 的服务端口为 8081，演示环境至少需要 8 GB 内存，验证并发数为 4。依赖为 Python 3.11 和 PostgreSQL 15，与 project_orion.md 的版本约束一致。本记录没有指定操作系统，不能根据使用 Python 推断系统一定运行在 Linux。

## Lyra环境
Lyra 的服务端口为 8082，演示环境至少需要 4 GB 内存，验证并发数为 2。依赖为 Python 3.12 和 SQLite 3。两个项目的端口和依赖不能互换；同机演示时应先检查端口占用与独立的数据目录。

## 性能条件
演示性能检查采用预热后的索引，并限制在固定的小型知识库和验证并发数内。文档没有提供生产 P95 延迟，也没有承诺百分之百可用性。索引首次构建时间应与查询时间分开统计，避免将冷启动与稳态延迟混为一谈。

## 维护
更新知识库后需要重新确认索引与文档版本一致。部署前检查环境依赖、端口和资源，失败时保留错误记录。维护者应记录测试日期、配置与数据版本；没有测量过的资源规格和吞吐量不属于本文件结论。
