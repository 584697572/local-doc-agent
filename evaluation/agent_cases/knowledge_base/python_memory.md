# Python 流式处理说明

本文用于内部回归测试，描述团队处理批量记录时采用的约定。示例中的数据规模和工作负载是假设场景，不代表生产性能承诺。

## 容器与迭代
Python list 一次性保存已经构造的全部元素，可以按下标访问，也能多次遍历。generator 使用惰性求值，在调用方请求下一个元素时才继续执行。二者都能参与循环，但保存数据和推进计算的方式不同。选择时应先确定是否需要随机访问。

## 内存
generator 通常只保留迭代状态和当前需要的元素，因此处理大量记录时可减少峰值内存。这个优势适用于消费方逐条处理且不把结果重新全部收集起来的情况。如果最终仍调用 list 收集所有结果，结果本身占用的内存不会消失。

## 速度边界
generator 并非任何情况下都更快。运行时间取决于计算工作、解释器开销和消费方式；需要反复遍历时，预先构造的 list 可能更合适。本说明没有提供固定的速度提升百分比，也没有对所有输入作性能保证。

## 工程使用
批量处理器采用先验证小样本、再测量峰值内存和总耗时的流程。读取方负责关闭底层文件，消费者异常退出时也需要释放资源。测试中应同时保留逐条消费和收集全部结果两种方式，避免仅凭语法形式判断内存收益。
